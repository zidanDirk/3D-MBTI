# 商业化接入说明

## 当前完成的产品能力

可作为未来收费内容的四项能力已可使用：深度人格报告、7 日成长计划、历史维度对比、完整报告导出。12/32/60 题目前均可体验，价格与订阅方案尚未设定。示例报告与用户实际报告有明确区分；示例打卡不写入真实历史。

当前是纯浏览器体验版，数据保存在用户自己的 localStorage。没有身份验证、支付收款、订单、订阅、服务端授权或云存储。`src/access.js` 的默认结果为 `mode: preview, paid: false`，列出全部体验能力。它提供未来读取服务端权益的适配点；仅替换该读取函数不会让当前应用变成安全的付费服务。

## 功能标识

| ID | 内容 |
| --- | --- |
| `deep-report` | 深度报告 |
| `growth-plan` | 行动计划与打卡 |
| `history-compare` | 两次结果对比 |
| `report-export` | 完整报告下载 |

可选商业模型包括按报告购买或会员订阅。定价、计费周期、退款政策、免费边界、认证与支付提供商须由产品方确定后实施；当前 UI 不展示虚假价格或可点击的假支付按钮。

## 建议的服务端契约（待实施）

- `GET /api/me/entitlements`：认证会话对应的权益 `{ mode: "server", paid: true, features: ["deep-report", ...], expiresAt }`。客户端可用于展示入口，不能作为安全授权依据。
- `POST /api/assessments`：题库版本、档位、题目 ID 和答案；服务端验证完整性、重新计算评分，并生成归属于当前用户的 assessment ID。不能接受客户端传入的可信最终评分。
- `GET /api/assessments/:id/report`：检查登录身份、报告所属用户和实时权益，再由服务端生成/返回收费内容。认证缺失返回 401，权益不足返回 403。
- `PATCH /api/assessments/:id/growth`：检查记录归属与权益，校验 day 为 1–7，幂等更新打卡状态。
- `POST /api/checkout`：产品 ID 与幂等键；价格、币种、订单归属由服务端决定，创建支付服务商托管结账会话。
- `POST /api/payment-webhooks`：校验签名、订单金额/币种/状态、幂等事件处理；只有已验证的支付事件可以发放权益。取消、退款和到期必须撤销或调整权益。
- `GET /api/assessments/:id/export`：再次检查归属与权益，在服务端生成收费导出文件或短时效下载地址。

## 上线前还需完成

1. 选定身份、数据库、支付渠道与服务端运行环境；服务端密钥不可进入客户端包。
2. 将需要保护的报告内容生成迁到服务端；当前本地 `reports.js` 是开放体验逻辑，不能用前端隐藏按钮或 localStorage 标志保护收费内容。
3. 用真实登录会话替换 preview 权益来源；前端按 `features` 控制入口，所有服务端内容接口仍独立校验。
4. 给本机历史增加用户确认的账号迁移/同步、删除与导出流程；未登录的本机记录不能被当成其他账号的数据。
5. 在支付沙盒中验证成功、失败、取消、重复回调、退款、到期与越权访问，再开启真实收费。
6. 完成实体手机/微信 WebView 的兼容性与下载流程验证，确认业务文案与服务规则。

未接入支付前保留明确的“体验开放 / 无扣款”状态，不宣称用户已经购买或获得订阅。
